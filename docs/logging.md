# CMD 출력 및 저장 이력

`python app.py` 또는 `python run.py`로 서버를 시작하면 자동 적용된다.

- `Logs/pms_YYYY-MM-DD.log`: CMD의 stdout/stderr, 접속·응답 로그, Flask/Werkzeug/Waitress 로그 및 오류 출력. 화면 출력도 그대로 유지한다.
- `Logs/audit_YYYY-MM-DD.log`: POST/PUT/PATCH/DELETE에서 실제 DB 커밋이 완료된 데이터 저장·수정·삭제 이력.
- UTF-8 텍스트이며 출력 직후 flush한다. 한국 날짜가 바뀌면 새 파일에 이어 기록한다. 서버 재시작 시 기존 파일에 추가한다.
- 기본 경로는 PMS 폴더의 `Logs`. `PMS_LOG_DIR` 환경변수로 변경할 수 있다. Logs는 Git에서 제외된다.

저장 이력 한 줄에는 한국 시각, 사용자 이름·ID·부서, 저장 항목, 사업번호/사업ID 등 대상, 경로, 요청ID, 입력 내용, 파일명, 커밋된 DB 작업과 값이 포함된다.

비밀번호·토큰·인증키 필드는 비공개로 기록한다. 직원 테이블의 SQL 및 바인딩 값은 비밀번호 해시가 포함될 수 있어 기록하지 않고, 비밀번호를 제외한 요청 내용과 반영 행 수를 남긴다. 파일 자체의 바이너리는 저장하지 않는다.

조회·로그인·회의록 조회수 및 자동 백업은 저장 이력에 포함하지 않는다. 롤백·실패한 커밋도 저장 완료 이력에 포함하지 않는다. 같은 내용을 재저장하면 반영 행 수 0으로 기록될 수 있다. 기록 시점은 HTTP 응답이 아니라 DB 커밋 완료 시점이다.

입력 내용은 사용자가 제출한 값이며 DB변경의 SQL·값은 커밋된 변경 명령이다. 수정 전 DB 값의 전체 스냅샷은 포함하지 않는다. 공통 `create_connection()`을 사용하는 저장 경로에 적용된다. 별도 DB 연결 또는 외부 프로세스에서 직접 저장하는 경우에는 해당 경로에 별도 연결이 필요하다.

디스크 오류로 로그를 쓸 수 없으면 CMD에 `[PMS 로그 저장 실패]`를 출력한다. 이미 완료된 DB 저장을 실패로 되돌려 표시하지 않는다.

검증: `python -m unittest discover -s tests -p test_file_logging.py`.
