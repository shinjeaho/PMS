# 사업 최근 업데이트일

- `projects.last_updated_at`: nullable DATETIME, 한국 시간(Asia/Seoul).
- 갱신 기록이 없는 기존 사업은 DB에 NULL로 유지하고 화면에는 `-`로 표시. 이후 추가·저장부터 실제 저장 시각으로 갱신.
- 과거 초기값인 2026-10-07 00:00:00은 마이그레이션 시 NULL로 정리. 실제 저장 시각이 기록된 사업은 유지하며 날짜별 숨김 처리는 사용하지 않음.
- 사업 관련 저장·수정·삭제 API에서 `touch_projects`를 commit 직전에 호출.
- 날짜 갱신은 원래 데이터와 같은 DB 트랜잭션에서 처리. 별도 commit 없음.
- 조회, 파일 열기, 회의록 조회수 증가, 전사 기준정보·직원·업무보고 저장은 사업 날짜를 갱신하지 않음.
- 사업 생성·복제·엑셀 사업 등록, 개요·상태·배치, 예상 인력·경비, 검토 예산·노트, 물량·경비 및 로그, 외주·진행률·지급, 계약변경·수령·성과심사·참여기술자·이슈, 코멘트·외부인력, 사업 파일 저장·삭제를 연결함.
- 회의록 업로드·수정·삭제 및 회의록 첨부파일 삭제의 갱신일 호출은 주석 처리하여 제외함. 회의록의 DB 저장과 별도 저장 이력 기록은 유지됨.
- 같은 값을 다시 저장해도 성공한 저장 시각으로 갱신.
- year 목록의 외주구분 오른쪽에 YYYY-MM-DD로 표시. 정렬은 저장된 시각 기준.

운영 서버에서 `git pull` 후 PMS를 재시작하면 DB 변경이 자동 적용된다. `app.py`, `run.py`, WSGI의 앱 생성 과정에서 실행되며 Git 자체가 DB를 수정하는 것은 아니다.

`pms_schema_migrations`에 적용 버전을 기록해 같은 변경을 반복하지 않는다. DB 잠금으로 동시에 시작되는 서버의 중복 실행을 방지한다. 최초 적용 계정에는 CREATE/ALTER/UPDATE/INSERT 권한이 필요하며, 실패하면 서버 시작을 중단하고 로그를 남긴다.

필요할 경우 수동 실행도 가능:

```powershell
.\.venv\Scripts\python.exe tools/migrate_project_updates.py
```

컬럼이 없으면 NULL 기본값으로 추가하고, 이미 있으면 유지함. 과거 초기값만 NULL로 정리하며 NULL인 사업에 날짜를 채우지 않음. 반복 실행해도 실제 저장 시각은 유지됨.

`ON UPDATE`를 사용하지 않아 조회 과정의 D-Day 자동 계산만으로 날짜가 바뀌지 않음.
